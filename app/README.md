# Demo application

A small FastAPI service written for this lab. It exists to prove that every layer works together: the request crosses the router (DNAT), Nginx, the application container, and finally reaches PostgreSQL on the private subnet.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/healthz` | The service itself is running (does not touch the database) |
| GET | `/db-check` | Runs `SELECT 1` on the database; returns 503 if it is not reachable |
| GET | `/visits` | Returns the total number of visits and the time of the last one |
| POST | `/visits` | Records a new visit (one row per visit) and returns the updated stats |
| GET | `/docs` | Interactive API documentation generated by FastAPI |

Example response: `{"total": 3, "last_visit": "2026-10-08T12:34:56.789012+00:00"}`. With an empty table: `{"total": 0, "last_visit": null}`.

## Design notes

- One row per visit instead of a single counter row: concurrent requests cannot overwrite each other, and each visit keeps its own timestamp.
- `created_at` is set by the database server (`server_default`), so timestamps come from one clock.
- `POST` changes data, `GET` only reads (REST semantics).
- The table is created at startup with `create_all`. If the database is unreachable at that moment the container exits, so it runs with `--restart unless-stopped`.
- The database connection comes only from the `DATABASE_URL` environment variable. There are no credentials in the code or in the image.

## Configuration

| Variable | Example |
|---|---|
| `DATABASE_URL` | `postgresql://app_user:<password>@10.0.3.10:5432/app_db` |

See `.env.example`. The real file stays outside the repository.

## Build and run

```
docker build -t lab-api:latest .
docker run -d --name lab-api --restart unless-stopped \
  --env-file ~/lab-api.env -p 127.0.0.1:8000:8000 lab-api:latest
docker logs lab-api        # expect: Application startup complete
```

The port is bound to `127.0.0.1` so the service is reachable only through the Nginx reverse proxy.

## Quick test

```
curl http://localhost:8000/healthz
curl http://localhost:8000/db-check
curl -X POST http://localhost:8000/visits
curl http://localhost:8000/visits
```

## Known limitations

- `/docs` and `/db-check` are exposed through Nginx like every other path. Restricting them is a planned hardening step.
- The connection pool size (10 + 20 overflow) is larger than a small lab needs.
- `DATABASE_URL` is not validated at startup; a missing variable gives an SQLAlchemy error instead of a clear message.
